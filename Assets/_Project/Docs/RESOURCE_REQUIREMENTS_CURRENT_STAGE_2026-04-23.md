# LostBreadcrumbs 현재 단계 리소스 요구사항

Updated: 2026-04-23

## 1) 현재 단계 판단 (리포지토리 기준)
- 코어 게임 루프/시스템은 코드로 상당 부분 구현됨 (맵 생성, 스테이지 루프, 적 AI, 능력, 저장/로드, 회귀 체크).
- 반면 `_Project` 영역은 **코드/ScriptableObject 중심**이며, 실제 콘텐츠(아트/오디오/프리팹)가 매우 적음.
- `Dummy` 기반 임시 구현이 다수 존재함 (`*Dummy*.cs` 10개 확인).  
  즉, 현재 단계의 핵심 병목은 **기능 구현 부족이 아니라 콘텐츠 리소스 부족**임.

## 5) UX 전략 (불필요한 UI 노출 방지)
- `DebugOverlay`/개발자 수치 패널은 기본 비노출, 디버그 키로만 열기.
- 전투 중 UI는 `목표/위험/쿨다운` 3종만 상시 노출하고, 상세 수치는 숨김.
- 이벤트 피드 문구는 최근 1~2개만 노출하고 자동 페이드.
- 같은 경고의 중복 출력 금지(우선순위 높은 알림 1개만 표시).
- 초반 3스테이지까지는 설명형 UI, 이후는 아이콘/신호 중심으로 점진 축소.

## 6) 즉시 실행 가능한 제작 백로그 (1주 기준)
1. **Dummy 치환 1차**: Player/Enemy/Portal/Pickup 프리팹 우선 제작 및 연결.
2. **에코 가시성 강화**: 에코 파형 VFX 3단계 + 안개 뒤 적 전용 강조 신호.
3. **필수 SFX 탑재**: 능력/적 감지/피격/알림 우선 적용 후 더미 루프 의존 축소.
4. **HUD 아이콘화**: 능력/위험/목표 텍스트를 아이콘+짧은 보조 텍스트 구조로 치환.
5. **세트피스 1종 완성**: 스테이지 3 기준 시각+음향+보상 피드백 포함한 수직 슬라이스 1개 완성.

## 7) 완료 정의 (Definition of Done)
- 플레이 10분 동안 더미 비주얼/더미 오디오 노출이 핵심 루프에서 체감되지 않을 것.
- 적 탐지/추적/위협 전환을 UI 없이도 시청각 피드백만으로 구분 가능할 것.
- 스테이지 1/3/5 플레이에서 "긴장-완화-결정" 리듬이 반복적으로 발생할 것.
- 회귀 체크(F11) 통과 + 플레이테스트에서 "무슨 일이 일어나는지 모르겠다" 피드백 감소.
