# Game Update Direction
Updated: 2026-05-10

## Direction Shift
The project direction has shifted from continuous escalation toward paced horror. The goal is no longer just "more pressure." The goal is a loop with breath: plan, risk, survive, recover.

## Near-Term Direction
1. Validate the new rhythm foundation.
   - Editor compile, scene wiring, F11 regression, release soak, and one short manual playtest are the next gate.

2. Convert phase math into phase behavior.
   - Calm: route reading and distant threat clarity.
   - Build: greed, speed, corrupted information, rising audio/fog pressure.
   - Spike: short survival test with strong tells.
   - Release: felt relief and next-objective clarity.

3. Keep player-facing rhythm diegetic.
   - Debug can say Calm/Build/Spike/Release.
   - Player UI should express rhythm through sound, fog, camera, enemy posture, echo quality, and priority cues.

4. Tie set-pieces to phase.
   - Stage 3/5/7 events should eventually align with Build or Spike instead of only stage number.

5. Protect fairness.
   - Spike must feel earned by previous choices or clearly telegraphed.
   - Corrupted hints belong mostly in Build; Spike should resolve consequences.

## Medium-Term Direction
1. Build phase-specific reward rules for breadcrumbs, risk cache, safe haven, and exit cache.
2. Add better Release language through lighting, audio, route whisper, and enemy recovery behavior.
3. Give each enemy profile a rhythm role: distant pressure, flank pressure, panic pressure, obsessive pressure, or counter-pressure.
4. Replace dummy presentation where it blocks playtest feedback.
5. Keep regression and soak checks as the guardrail before major tuning changes.

## Release Readiness Standard
A build should not be considered release-candidate stable until rhythm checks, pressure checks, objective checks, save/load transient cleanup, death reset, matrix, chase readability, and release soak all pass in the same workspace state.
